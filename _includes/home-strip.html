Album items link to albums.oinam.com, books to posts here — and `relative_url` prepends the baseurl, so handing it an absolute URL is wrong the moment a baseurl exists. ⚠️ `href` — THE HEADING LINK — TAKES THE SAME TEST, added 2026-09-01 when the Albums heading started pointing at https://albums.oinam.com. It had been an unconditional `relative_url` because both callers were internal; an absolute URL through that filter is the same latent bug as above. It also wants the ↗ every off-site link on this site now carries. ⚠️ NO `target` AT ALL — AN OFF-SITE LINK OPENS WHERE THE READER SENT IT. 2026-09-01: "I don't want to break convention and force a target=_blank." Forcing a new tab overrides a choice that belongs to the reader, who can ask for one with a modifier-click or a middle-click on any link. The ↗ tells them the link leaves the site so they can make that choice knowingly; it does not make it for them. ⚠️ AND WITH NO TARGET, `rel="noopener"` IS DEAD WEIGHT. It only means anything when a new browsing context is created. There is none here, so it is gone rather than kept "to be safe" — an attribute that does nothing still has to be read and reasoned about by whoever comes next. ⚠️ THE NAMED-WINDOW IDEA IS CLOSED, and the measurement is kept because it is not guessable from the markup. The idea was to give every off-site link ONE window name so they would share a tab instead of opening a dozen. It works — but a named target CANNOT carry `rel="noopener"`, because reuse finds the window BY NAME and that lookup only succeeds if the two contexts are "familiar", which across origins only the opener relationship provides. Measured in Chrome, two cross-origin links sharing a name: target="_name" -> 2 clicks, ONE tab (reused) target="_name" rel="noopener" -> 2 clicks, TWO tabs So it was reuse or noopener, never both — and `rel="noreferrer"` is no third option, it implies noopener. It went `_oinam-albums` -> `_oinam` -> `_blank` -> nothing, in one afternoon. ⚠️ A grep over built HTML called every one of those states correct; only the browser saw the difference. ⚠️ AN OFF-SITE HEADING IS MARKED TWICE, AND BOTH HALVES ARE REQUIRED. It gets the ↗ from icons/external.svg and an `aria-label` reading "… (external link)". The glyph is `aria-hidden`, so WITHOUT THE LABEL the fact that the link leaves the site would exist only for people who can see it. The label overrides the accessible name and still opens with the visible word ("Albums …"), which is what keeps voice control working. ⚠️ The label says "external link" and not "opens in a new tab" — it said the latter while a `target` was forced, and the moment that came off, the sentence became false. An aria-label that describes behaviour has to be re-read every time the behaviour changes. The INTERNAL branch gets none of it. A link to a page on this site opening a new tab is the behaviour every other link here does not have, and the mark would be a lie. IMAGE PATHS, in three branches. `img` starting with "http" is a remote file and is emitted verbatim; one starting with "/" is site-absolute and also verbatim; anything else is a bare filename resolving under /static//. Slice rather than `contains "/"`, because a filename in a subfolder would contain one too. ⚠️ THE "http" BRANCH ALSO SKIPS `relative_url`, and both halves matter — the same fix, for the same reason, as _includes/card-grid.html. This strip reads _data/albums.yaml, generated from albums.oinam.com's feed, where every `img` is an absolute media.oinam.com URL. ⚠️ And this file is now the ONLY caller that does — /album/ was deleted on 2026-09-01, so card-grid.html's copy of the branch is unexercised. It is kept there deliberately, so the two includes stay the same shape; do not delete it as dead code without reading the note in that file first. ⚠️ ALT: a bare `if item.alt` test, NEVER `item.alt | default: item.title` — again identical to card-grid.html, and HERE IT IS LOAD-BEARING. The `default` filter substitutes on the EMPTY STRING, and _data/albums.yaml sets `alt: ""` deliberately on the photos albums.oinam.com left uncaptioned, whose titles are their FILENAMES ("London — IMG_9018.jpeg"). Revert this one line and the home page reads filenames aloud to a screen reader. Books carry no `alt` key at all, so they are nil and still fall back to the title. See scripts/fetch-albums.rb.
