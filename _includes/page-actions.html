USAGE — nothing is required; every page can include it unchanged: {% include page-actions.html %} Optional overrides: url the page URL to act on (default: page.url) title used in the prompt sent to the AI (default: page.title) kind the noun in that prompt (default: "page") On a post that is literally all it takes; `kind="post"` only improves the wording of the prompt. ⚠️ THE .md TWIN IS THE WHOLE MECHANISM. Every link here points at `.md`, the plain-text twin that scripts/build-agent-markdown.mjs writes for every post and page ("append .md to any page URL" — see _docs/agents.md). The AI links do not upload anything or embed the page; they open a new chat pre-filled with a prompt asking the model to READ that URL. That is why the twin has to exist and has to be public. ⚠️ THE URL EXPRESSION IS COPIED FROM _layouts/default.html, which emits the for the same file. The two must agree, so they are the same three filters: append a sentinel, drop the trailing slash with it, then append .md. /cv/ -> /cv.md. Change one, change both — a mismatch here is a link to a 404 that nothing else would catch. ⚠️ THE TWINS ARE BUILT IN CI ONLY. `jekyll serve` never runs that script, so under a local server every link in this bar 404s. That is the same pattern as the esbuild and hash-assets steps — but those are invisible to a reader and this is a visible link, so it is worth knowing before reporting it as broken. Do not add a local build step for it; run `node scripts/build-agent-markdown.mjs` after a build if you need to check them. ⚠️ NO BRAND LOGOS, deliberately. His spec was "Open In [OpenAI] [Claude] | [Icon: Markdown] [Icon: PDF]" — note that "Icon:" appears only on the last two. The `+` → `%20` pass is because url_encode uses form encoding for spaces.
