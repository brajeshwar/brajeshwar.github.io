--- layout: default title: Archives styles: css/archives.css --- {%- comment -%} One Liquid grouping drives both the jump-nav and the list, so they can never disagree about which years exist. group_by_exp keeps site.posts' order, which is newest-first, so the years come out descending with no sorting needed. Replaced the older running-`date`-variable approach, which opened and closed the from two different branches of the loop and shadowed Liquid's own `date` filter name with an assign. {%- endcomment -%} {%- assign years = site.posts | group_by_exp: "post", "post.date | date: '%Y'" -%} {%- comment -%} No container class: this page lists, it doesn't read, so it takes `main`'s default width — the site-wide 1280px — rather than the 665px reading measure that .container-ideal would impose. The scrubber is a real grid column here rather than something floated in the viewport margin; at this width there is no margin left to put it in. {%- endcomment -%}

ids below — those already existed, so /archives/#2024 has always worked; this just makes them reachable without scrolling back to the top. Pure CSS sticky, no JS (guardrail 4). pagefind-ignored: 26 bare year numbers would be noise in the index, on a page that is already a list of every post title. {%- endcomment -%} {%- comment -%} Labels are the last two digits (26, 25 … 01), iOS-Contacts style — but the href and the caption id stay the FULL year, so /archives/#2024 keeps working. aria-label restores the full year for screen readers, which would otherwise hear "26". No ambiguity to worry about: site.posts spans 2001–2026, and the 2100-dated drafts in _posts/todo/ are future-dated, so Jekyll never builds them into this list. {%- endcomment -%}
