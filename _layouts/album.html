The default is "unless the page already rendered an h1", which keeps /hire/, /random/ and /styleguide/ — pages that write their own — from getting two. `content` is rendered HTML by the time a layout sees it, so the test is exact and needs no per-page opt-out to keep in sync. 2. EXCEPT when the page asks explicitly. /now/ is eleven `# YYYY` sections (2026-08-08: "I have used '# YYYY' for me to edit easily, we can still have another on the top as the title") and /legal/ carries `# Privacy Policy` and `# Terms of Use`. Both trip the content test and both still want a title, so `force_title: true` or any `title_style:` overrides it. ⚠️ That means those pages ship MORE THAN ONE h1, which is his call and worth knowing: the fix that keeps the markup honest is `## YYYY` in now/*.md, and he has said he prefers the single hash for editing. 3.
