The `_redirect` collection was configured in _config.yml long ago and never used: the folder was empty and this layout did not exist, so the machinery was declared and absent. It exists now because a URL moved, and guardrail 2 says every URL is preserved. ⚠️ NO JAVASCRIPT. A `` is the only redirect a static host can perform without a server rule, and it works with scripting disabled — which a JS `location.replace` would not. `0;` so it is immediate. `rel="canonical"` on the TARGET tells a crawler the destination is the real page, and `noindex` keeps this stub out of the index while `follow` lets the link equity pass through. Between them a search engine treats this the way it would a 301, which is the closest a static file gets. The visible link is not decoration. If the refresh is blocked — some extensions and readers do block it — the reader lands on a page that says where it went and offers the door, rather than a blank screen. A page using this layout needs only front matter: --- layout: redirect permalink: /old-url/ redirect_to: /new-url/ sitemap: false --- ⚠️ `sitemap: false` goes on the PAGE, not here. Front matter in a layout does not propagate to the documents that use it, so the stub was listed in sitemap.xml on the first attempt — verified by grepping the built file.
